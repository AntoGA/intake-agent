## Исправления

Запись результата и ошибки worker выполняется только если status=processing и
attempts совпадает с номером захваченной попытки. Если попытка уже потеряна,
устаревший worker не меняет строку и не добавляет событие. База не мигрируется.
Core проверяет типы/непустое содержимое/размеры полей; API отклоняет поля из пробелов
через Pydantic. Авторизация сравнивает UTF-8 bytes и возвращает 401 для неверного
Unicode-заголовка. Правила разделения ADMIN_TOKEN/INGEST_TOKEN сохранены.

## Границы проверки

Telegram, IMAP и внешний LLM не вызывались: используются synthetic inputs/mocks.
Не отправлялись сообщения и не принимались реальные заявки. Система по-прежнему
не отправляет согласованный draft клиенту. Single-worker deployment остаётся
рекомендованным: fencing предотвращает stale writes, но не предотвращает повторный
LLM-вызов после истечения lease. Нет heartbeat/cancellation для долгой генерации.

Остаётся отдельно проверить ограничения ответа LLM/redirects trusted endpoint,
backpressure, реальные источники, восстановление backup и operational deployment.
Это PoC-аудит, без заявлений о production или измеренном ROI/SLA.
`main` не изменяется, merge не выполняется.
